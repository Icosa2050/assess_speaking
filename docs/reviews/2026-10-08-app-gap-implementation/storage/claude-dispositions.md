# Claude CLI review dispositions

Three logged-in, read-only Claude CLI reviews were run under the standing repository authorization. Inputs contained selected source/tests/docs, without credentials, learner recordings or learner reports. The third review disabled tools and reviewed only its supplied four-file bundle. These are independent static findings, not test execution or blanket approval. Raw inputs/results and hashes are retained here. The initial restricted CLI attempt reported missing login; the approved elevated CLI completed.

The first review identified an event-loop deadlock risk from RLock guard acquisition; guard acquisition and release now run in the thread pool. Maintenance uses the same History file lock as normal writers and an exclusive cross-process lease. CLI analysis holds the shared lease for its entire run. Other material fixes include canonical History projection on restore, startup recovery notices, durable completion receipts with idempotent completion, definite IndexedDB-failure compensation, disabling cancellation after publication starts, removal of unsafe per-chunk lease heartbeats, retaining recovery metadata until it is safe, actual Mail attachment validation, Apple Events usage/entitlement declarations, and preserving non-secret analysis usage provenance.

The follow-up review correctly found the upload registration sidecar made every upload appear shared, completed jobs made every ordinary attempt unpurgeable, retry links were checked in a nonexistent CSV column, JSONL and previous report revisions survived removal, and cross-volume tombstones could fail. Purge now inventories the actual managed upload/sidecar layout, completed jobs/checkpoints and all report revisions; streams a filtered JSONL replacement; reads report retry metadata; protects other jobs/reports/rehearsals; and uses same-directory tombstones. Current-profile browser references and a fresh preview fingerprint are required by the direct API. Restart-mid-purge, browser purge and direct API precondition regressions were added.

Selective restore now skips existing backend/browser identities and lists them in the preview, recovering missing items into a populated journal without overwriting originals. Missing browser audio has an explicit opt-in backup mode with omission inventory and retake flags. Commit uses a longer bounded timeout. The status GET is read-only. Tests retain and explicitly close their shared guard handles. Stale production-storage docs/messages were revised. A recovery notice can still appear when a maintenance transaction is active; this is an informational UX limitation, not an unlocked lease or automatic rollback.

The final focused review found one P1: optional cache-directory cleanup could strand a completed purge when a referenced cache file was deliberately retained. This was reproduced in a regression. Preview now omits folders with retained files from directory cleanup; already-committed empty-directory cleanup is best-effort and cannot strand the lease. A second injected-cleanup-failure test verifies that restart remains writable. Both passed with the final 30 storage/API tests. The review found no other P0/P1 in its supplied scope; it did not execute tests. Its input preceded this last fix, so the fix is supported by the reproduced regressions and local review, not an invented post-fix Claude approval.

Mail attachment copies are private and independent of expiring temporary bundles. Native testing observed the exact test recipient and attached ZIP, followed by the app's truthful draft-prepared result; the unsent synthetic draft was discarded. No message was sent. Public signing, hardware microphone quality, independent human coaching evaluation and receiver retention were not established by these reviews.
