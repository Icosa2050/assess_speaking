# Two-store backup and recovery contract

Production backup, additive restore, archive/Undo and separately confirmed permanent removal are implemented. `benchmarking/backup_prototype.py` remains an explicitly marked disposable experiment; it is not the product implementation. Implementation and verification are recorded in [storage delivery evidence](../reviews/2026-10-08-app-gap-implementation/storage/README.md).

The backend owns History CSV, report revisions, uploaded/recorded audio, session JSONL and operational jobs/checkpoints. IndexedDB `vostavo-rehearsals` v2 owns rehearsal sessions, part blobs and its restore marker. The v1 upgrade checks existing stores and preserves populated profiles. A backup covers the calling browser origin/profile and the backend journal; it cannot discover other browsers' independent storage.

The version 1 ZIP includes stable attempt/rehearsal/part IDs, timestamps, retry/report links, eligibility and analysis provenance, checksum-named shared media, MIME types, per-file sizes/SHA-256 and explicit omissions. Credentials, account state, provider settings, jobs and stage caches are excluded. Reports are sanitized and paths rebound on restore. Restored provenance records the archive, original source-report and sanitized-report hashes; these are integrity checks, not authenticity signatures. Jobs are not resumable. Existing identities are kept unchanged, listed as skipped in the preview, and missing identities are added. Unsupported schemas and corrupt, duplicate, traversal, encrypted, symlink or unlisted entries are refused before publication.

The expanded archive limit is 512 MB, the manifest limit 16 MB and entry limit 32,000. Transfers use bounded binary bodies; recordings remain native Blobs rather than base64. Staging checks free disk space and browser transactions report quota failures. Missing reports/audio normally block export; explicit opt-in lists each omission. A recorded rehearsal without its blob is marked `missingRecording`, reset to require a retake, and included in the missing inventory.

Lock order is the literal global browser Web Lock `vostavo:journal-maintenance`, backend maintenance lease, then per-rehearsal locks/transactions. Browser saves share the global lock. Internal staged writes require an active opaque lock capability. Backend normal mutations and complete CLI assessment runs use a shared cross-process file lock; maintenance acquires exclusive ownership without waiting. Active workers or mutations prevent acquisition. Terminal workers are joined briefly before exclusion checks. CSV writes and session JSONL appends use the same respective file locks as maintenance. HTTP guard acquisition/release runs in the thread pool, preventing an event-loop deadlock.

There is no filesystem/IndexedDB atomic transaction. Backend phases are `prepared`, `backend_staged`, `backend_committing`, `backend_committed`, `complete` and `rolling_back`; the browser independently records `prepared`, `staged` and `committed`. Both stores stage first. The backend publishes with previous indexes retained, then IndexedDB commits atomically. A definite browser transaction failure compensates backend publication. A lost completion reply retains markers; recovery consults the backend's durable receipt before finishing or rolling back. Receipt publication precedes cleanup and completion is idempotent. No clock expiry releases incomplete publication. Startup/Settings surface pending recovery; malformed journals retain originals and refuse mutations. Rollback removes only imported identities, retaining unrelated later History entries.

Archive hides an attempt or rehearsal and retains its media and identity for Undo. Archived backend reports remain readable for saved rehearsal links. Permanent removal requires a fresh inventory fingerprint and current-profile browser reference snapshot; it refuses saved rehearsal/retry parents, active/resumable jobs and shared caches. Direct API callers must provide that snapshot too. The authenticated local API trusts the calling profile's inventory; this does not attest unknown external origins. Exported ZIPs and email/receiver copies are independent and remain available.

Attempt purge removes owned report revisions, completed job metadata/checkpoints, unshared audio and its upload-registration sidecar. Session JSONL is streamed into a filtered replacement. Each file first moves to a same-directory tombstone, supporting custom report roots on another volume. A durable purge journal holds the previous archive index and replacement checksums. Before the commit decision, restart restores tombstones and the original JSONL; after it, restart completes cleanup. A conflicting externally changed file is retained and reported for manual recovery. Spending/account ledgers are retained. Rehearsal purge atomically removes its IndexedDB session/blobs; its analysed backend attempts require their own removal action.

Native backup Save uses the existing `rfd` dependency and private atomic copies. Cancel keeps the generated ZIP available for Retry; Open uses the native webview file chooser and the same validated restore flow. Native support saving remains separate from learner backup. macOS support email opens an editable Mail draft with a ZIP attachment and an explicitly entered recipient. It never sends automatically. A private copy under `support-email-drafts` is retained independently of temporary bundle expiry so delayed Mail attachment reads remain valid. This copy and Mail/receiver retention are separate from the temporary package's 24-hour cleanup; no receiver-deletion guarantee is made.

Tests cover cross-root restore, selective recovery into a populated journal, preservation of eligibility/shared media, archive/Undo, schema preservation, malformed archives, disk/index/move failures, restart during publication/purge, unrelated-row preservation, cross-process exclusion, current-profile transfer, v1 migration, stale/concurrent tabs, browser quota compensation, lost completion acknowledgement, direct API exclusion and removal preconditions. Physical microphone quality, human coaching calibration and public signed-release acceptance remain separate gates.
