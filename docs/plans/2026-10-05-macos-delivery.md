# macOS delivery implementation and acceptance plan

Status: implemented, reviewed by Claude CLI, and locally tested. Internal DMG acceptance passed; external release acceptance gates remain. Scope: Apple Silicon Vostavo, internal DMG now and signed/notarized release mode using the same build. Existing signed-DMG design remains the release goal.

## Outcome

A DMG containing a Vostavo.app that runs without the repository, Python, Node, Homebrew, or system FFmpeg. Learner state lives outside the application bundle. Build output includes checksums and an evidence report. Public distribution must use Developer ID signing and notarization; ad-hoc artifacts are explicitly marked internal.

## Implementation order

1. Package runtime preparation: replace all three subprocess FFmpeg paths (chunking, non-WAV conversion and upload duration validation) with streaming PyAV resampling into bounded 16 kHz mono PCM WAV chunks. Preserve word-offset/cleanup behavior; test actual decoding with PATH scrubbed and malformed media. Use a separate cancellable/timed decoder subprocess with an explicit helper validation subcommand for the duration guard. Update diagnostics and media error classification coherently. Call multiprocessing.freeze_support before backend imports in the frozen entry point.
2. Backend packaging: create a separate clean Python 3.12 arm64 environment from a resolved production-only lock and pinned PyInstaller. Freeze an onedir helper app with application modules, multilingual resources, samples, native dependencies and certifi CA data. Explicitly collect dynamically imported provider and ASR modules. No .env, recordings, user settings or credentials in artifacts. Include faster-whisper VAD assets, uvicorn dynamic modules and macOS Keychain backend metadata; exclude development-only packages. Set SSL_CERT_FILE to the bundled certifi CA file. Record architecture, versions and deployment targets.
3. Desktop process lifecycle: resolve helper relative to current executable; installed mode fails visibly if helper is absent. Keep API overrides and repository launching only in debug builds; release binaries contain no repository fallback. Rust owns a child in installed and dev mode, launches from a writable user directory, uses a backend-owned port-0 bound socket and readiness-file handshake, waits for authenticated health with a bounded timeout and records startup logs. Hold a single-instance lock, place the helper in its own process group, retain/drain output to files. On exit send SIGTERM and then bounded process-group hard-kill fallback; a stdin EOF watchdog stops the helper if the shell crashes. Errors name the log location in a native macOS dialog.
4. Local API session protection: create a random per-launch token, inject it into the desktop bridge, require it on packaged API routes. JSON/upload requests send a header; media routes accept the token only on explicit read-only recording/sample endpoints because HTML audio cannot supply custom headers. Set access_log=False, add Referrer-Policy: no-referrer and use constant-time token checks. Frozen serve mode refuses missing tokens. Health is authenticated; OPTIONS preflights are allowed. Keep current browser/dev API behavior when no session token is configured. CORS and origin checks remain active. The startup probe verifies token ownership, not merely any healthy server at the chosen port.
5. Bundle assembly: production frontend + Rust executable + nested frozen helper, icon, microphone usage description (all five UI locales), audio-input entitlement, minimum OS version derived/verified from included binaries. Build owned app-data/cache paths through existing backend defaults/migrations. Enforce matching Rust/Tauri/helper/artifact versions. Create app and DMG using native macOS tools, preserving symlinks.
6. Signing mode: explicit internal ad-hoc mode for local tests; release mode fails closed without a Developer ID identity and named Keychain notarization profile. Sign nested Mach-O code inside-out, sign helper then outer app, notarize/staple app before constructing/signing/notarizing/stapling DMG. Verify codesign, spctl and stapler; record result and SHA-256. Never change signature after final verification. No Apple credential creation or agreement acceptance in this implementation.
7. Artifact tests: mount DMG read-only, copy to isolated Applications-equivalent directory, eject, launch with sanitized PATH and cwd=/, fresh app-data/cache, and no repository fallback. Verify health, packaged metadata, rejected missing/wrong token, sample APIs, uploads and disk-backed history. Exercise actual bundled ASR + spawned assessment worker using English/Italian samples; test deterministic-only local feedback without paid external models. Test warm cache and cold model download if network available. Native UI launch and microphone permissions are a separate macOS webview acceptance check, not claimed from Chromium.
8. Regression checks: focused Python backend/media/lifecycle tests, Rust resolver/process tests, frontend tests/typecheck/build and existing bilingual upload/microphone journeys. Test occupied ports through backend-owned allocation, malformed backend startup and shutdown cleanup. Provide exact repeatable build/test commands and all remaining external acceptance steps.

## Validation boundaries

Automated CLI helper tests cover frozen dependencies, decoding, multiprocessing, API, persistence and isolation. Chromium tests cover the shared frontend. Inspect native app through macOS UI automation for production rendering and startup. A physical microphone and fresh-user TCC prompts require an interactive user session; no reset of the user's privacy database. A clean second Mac and genuine browser-downloaded quarantine Gatekeeper acceptance remain release checks when no signing identity is available.

## Implementation review revisions

Claude implementation review: `docs/reviews/2026-10-05-dmg-implementation-claude.md`. The main and media tokens are independent random values supplied through held stdin; media query credentials cannot authorize API headers. Release compilation explicitly enables Tauri's custom-protocol feature to embed production assets. Native navigation is restricted to the app origin. Readiness writes are atomic. Launch-directory names contain an independent nonce. Builds run locked npm ci with lifecycle scripts disabled and a scrubbed installation environment, plus native RPATH/legacy deployment-target checks. Internal ad-hoc helper uses a library-validation exception because no Team ID exists; Developer ID releases retain library validation. Signed-helper self-test is a mandatory build gate.

Debug mode launches the owned repository backend; the old unmanaged API override was removed to keep ownership and shutdown consistent. This replaces the earlier proposed debug API override. Default standalone repository API behavior is retained for web development.
