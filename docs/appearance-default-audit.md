# Appearance first-run default

Decision (2026-10-30): use **System** for a new installation. Keep explicit Light and Dark choices and their saved preference. The pre-paint initializer and Tauri loading and main windows resolve System against the operating system theme before content appears.

The decision is supported by the computed Playwright audit in `frontend/tests/e2e/visualRefreshSmoke.spec.ts`. It covers de, en, es, fr, and it in Light and Dark at 1360×900 and 1100×760. Each locale and theme covers home, runtime setup, history and empty history, library and its error, guide, settings, Your Data, journal error and confirmation dialog, rehearsal, empty review, session setup, speaking, assessment wait, review, failed assessment, and cancelled assessment. PR #36 added native draft storage but no additional UI route. German practice remains hidden.

All 380 locale/theme/state/desktop combinations passed computed text contrast of at least 4.5:1 and sampled essential boundary and keyboard focus contrast of at least 3:1. The audit checks clipped text, horizontal overflow, and all exposed controls at a 550×380 CSS viewport representing 200% zoom. Long history and setup action text are regression probes. Guide and empty history have no essential border sample; their text, focus, and control reachability are checked. The audit uses real computed CSS values and fails on a reverted history clamp or setup action `nowrap` rule.

The first-paint browser test covers absent preference under both operating system themes, explicit Light/Dark, and explicit System on the loading and main pages. The appearance unit test executes the pre-paint initializer to check parity with the state default. The audit runs in the bounded default Playwright CI lane and its screenshot/result index is attached to the implementation PR.
